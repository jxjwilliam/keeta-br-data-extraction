# Keeta 剩余 14 字段调查

调查日期：2026-10-22。基于 POCO X6 5G 实机页面、当前脚本和已保存证据；不是通过公开 API 获得。

## 结论

16 个已填字段不是 App 的覆盖上限。v4 原先只解析 Checkout，未进入店铺详情和订单页，并主动留空 ETA。

实机新增确认 3 个直接来源字段：`shop_address`、`shop_status`、`user_completed_orders_count`。用户本轮确认了 ETA 向上取整分钟及账号类型映射，因此再有 3 个可计算字段：`ceta_min`、`ceta_max`、`account_type`。在地址确实选中、账号会话一致、店铺匹配及同轮采集的前提下，原 16 项加上这 6 项，目标可到 22/30；本轮没有产出声称 22 项齐全的新 Excel。

## 逐字段来源

| 未填字段 | 实测或可行路径 | 状态及实现约束 |
| --- | --- | --- |
| `account_id` | 账号页、账号详情或可信账号台账 | 账号首页/设置页未见内部 ID。邮箱、昵称不能替代。 |

| `crawl_lat` | 当前选中配送地址的地图点/地址台账 | 未取得。手机在加拿大的 GPS 不等于巴西配送地址点位。 |

| `shop_lat` | 店铺详情内地图、地图跳转参数或授权数据 | 详情有 Google Map 和 Map Marker，但当前 XML 未给坐标。尚未验证地图跳转 URL。 |
| `shop_lng` | 同上 | 未取得。地理编码须标注补充来源与精度。 |

| `ceta_max` | 同上 | 午夜附近允许次日窗口；过期、歧义或超过 6 小时的窗口暂留空，避免把负值截成 0。6 小时是解析器的保守校验边界，不是业务 SLA。 |

| `shop_status` | 店铺详情 | 实测独立 `Open`，可填 open。`Closes at 22:30` 是营业时间，不能据此填 close；导航失败也不等于 close。 |

## 额外发现：原有字段也需要更严格的验证

旧 `checkout-top.png` 的地址栏仍为 `Select a delivery address`。Rua Jandaia 显示在提示气泡内，因此不能证明已经选中结算地址。旧工作簿原样保留，但其 `crawl_address` 的已确认状态需撤回。修改后的代码遇到该提示时，不填 `crawl_address`，也不从气泡推导城市。修复流程应明确选择用户指定的已保存地址，重新抓完整报价。

因此，22/30 是补齐有效地址后的一轮目标，不是本次已验证的新工作簿数量。字段数量不能代替字段来源质量。

另外，旧 Excel 的 `crawl_time` 读取为 16:33:17，而 JSON 为 13:33:17−03:00，说明展示导出链需要修正时区转换。后续应导出明确的圣保罗本地时间，并在来源说明保存时区；CSV/JSON 的 ISO 时间可作为核验基准。

## 已改代码

`scripts/keeta_scripe-v4.py`：

- 新增 `context_fields()`：解析详情页的精确 Open/Closed 和 Address，以及订单页明确空历史；不将可见订单卡数量当累计完单数。
- 新增 `account_type()` 与 `eta_minutes()`：使用用户确认的口径；处理午夜、过期和不确定时间窗。
- `--inspect-context-dir` 可独立生成上下文事实，避免覆盖结算样例。
- `--context-dir` 可在采集/解析结算时加入上下文；要求店名一致、各来源时间距离结算不超过 5 分钟。操作者还需确保同设备同账号、地址未改变；时间和店名校验不能代替账号身份校验。
- 地址提示不再当作有效已选地址。

运行与依赖见 `docs/keeta-continuous-guide.md`。基于脱敏实测 XML 的 8 个离线测试覆盖上下文解析、非空历史不误计数、Closes at 不误判关闭、地址气泡、ETA 向上取整/跨午夜/过期及账号类型边界。
