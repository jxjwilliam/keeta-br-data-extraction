# 连续逐条采集

## 用户结果

每次新会话生成一组带圣保罗启动时间的文件：

- `outputs/final/continuous_YYYYMMDD_HHMMSS.csv`
- `outputs/final/continuous_YYYYMMDD_HHMMSS.xlsx`

同一会话每成功一条更新一次。CSV 是提交记录的即时快照，XLSX 为同组记录的工作簿快照。尚无成功记录时 CSV 只有标题，XLSX 尚不存在；空文件不表示采集成功。

中断不会清空已提交记录。内部 SQLite 账本每条事务提交并同步落盘，CSV/XLSX 在临时文件写完后原子替换当前会话的快照；较早完成的文件在新快照写好前仍完整可读。若数据库已提交但进程在生成快照前中断，恢复时从账本补齐。新会话使用不同文件名；恢复只追加到选定会话。

## 执行

依赖及 Codex XLSX 运行时见 `docs/keeta-rerun-guide.md`。手机 USB 连接、已登录、已解锁，建议启用充电时保持唤醒。

```bash
python3 scripts/keeta_stream.py --serial 979f0245 --interval 30
```

恢复现有会话：

```bash
python3 scripts/keeta_stream.py --serial 979f0245 --interval 30 --resume outputs/internal/streams/continuous_20261023_123648
```

Ctrl+C 停止；已提交记录不删除。进程异常、锁屏、账号验证、购物车冲突、地址无法确认、连续三店失败时暂停，并在内部记录原因。不要把“进程启动”当作“已成功写入数据”，以 SAVED 条数及结果行数为准。

## 采集边界

- 自动读取订单空历史（明确 No orders yet 时为 0），解析账号类型；非空列表不数可见订单卡代替累计完单数。
- 滚动列表、进店、读取商家详情中的明确营业状态和地址、处理明确标记 Required / Select 1 的单选必选组（选第一个可读选项，以 Done 状态为完成依据）、进入 Checkout；已有可结算购物车时优先读取，不重复加购。
- 规格选择写入商品信息与内部证据；可选项目不自动勾选，复杂或不完整规格仍可能跳过。保留用户保存的配送地址。结算若仍要求选地址，只尝试已保存的 Rua Jandaia；无法确认时不写有效记录。
- 同屏多商品支持逐项汇总核算；跨页商品不完整则拒绝导出。支持费用行原价金额加 Free 的免费配送格式，明确记为 0。核对商品、折后费用、原价与优惠及跨页总额；未展示字段留空。店铺名必须与详情一致。
- 不提交订单，不操作支付，不修改账号、优惠或安全权限。出现限流或验证提示即暂停，不尝试绕过。
- 当前仅为连续采集 PoC，页面差异、购物车、商品规格、营业时间和起送价仍可能造成跳过或暂停。尚不保证跨店连续成功率。

## 中间文件与空间

`outputs/internal/streams/<会话>/` 保存账本、字段来源、错误和原始证据。默认仅保留最近十次尝试的 PNG，较早的 XML 压缩为 gzip，保留 JSON 来源与所有已提交记录。通过 `--keep-screenshots 0` 可不保留尝试截图；调整只影响当前会话，不清理旧历史。

中间 XLSX 只保留一份当前快照，不为每条记录另存大型版本。保存工作簿失败时 CSV/账本继续保留，并记录错误。

## 离线测试

```bash
python3 -m unittest discover -s tests -v
```

测试包含恢复不丢行、重复记录不追加、0 与空值区别，以及快照更新被打断后旧 CSV 完整、账本可恢复新增行。测试不调用手机，不把测试数据写入正式输出。
