# 连续采集与恢复

本指南对应当前 `scripts/keeta_stream.py`。安装/新建/恢复命令统一见 [README](../README.md)，依赖见 [运行资源](resources.md)，设备问题见 [排错](keeta-debug-guide.md)。状态在 [TODO](../TODO.md)。

## 参数

| 参数 | 当前行为 |
| --- | --- |
| --serial | ADB设备编号，当前X3为f753a0f3 |
| --interval | 店间等待秒数，实际下限180；不是平台配额 |
| --max-attempts | 每进程尝试上限，默认3；README显式20 |
| --resume | 现有会话目录；省略则创建圣保罗启动时间戳会话 |
| --keep-screenshots | 最近几次尝试保留PNG，默认10；0表示不保留尝试PNG |
| --stop-at / --run-timezone | 当天截止HH:MM及其时区，默认America/Vancouver；到时停止设备采集并保存起止时间 |
| --access-restored | 仅在人工确认恢复后归档访问暂停标记；不自动绕过限制 |

Ctrl+C停止；每次成功或部分采集先事务提交账本，再原子替换CSV/XLSX。同一设备/会话不得同时启动多个进程。换账号或设备新建会话。需要人工介入时暂停。

## 数据与成功率

每会话输出 `outputs/final/continuous_YYYYMMDD_HHMMSS.csv/xlsx`，前30列为业务字段，追加5列：尝试编号、状态、已填字段数、错误原因、金额校验通过标记。

- complete：地址明确且商品/费用/已用优惠/跨页总额校验通过，不是30字段全满。
- partial：有部分可核实业务字段；金额只取独立可见行，不用失败校验的派生值补齐。未知留空，0算已填。
- failed：没有有效业务字段；navigation：误入非店铺页，不作为店铺结果。
- 分母为有证据目录的进店尝试（complete/partial/failed）；同店不同尝试分别计数，同一次离线升级不重复计数。未识别店名的列表导航/连接错误不计入。
- 完整率=complete/分母；不是首次采集成功率，也不是“所有字段全部取得”的比例。Excel“成功率”页另列部分/失败数量及字段覆盖率。

CSV最先更新；XLSX失败不撤销已提交数据。内部records表保留完整记录，attempts表保留部分/失败审计，导出按attempt_id合并升级。同一尝试重新解析不会重复留一条失败。

## 字段与采集条件

默认使用用户指定的Rua Jandaia, 7550, São Paulo, SP保存地址。已选地址直接读取；要求选址时仅选择该地址。账号、优惠、支付设置保持原样，不应用券、不支付、不下单、不清未知购物车。

同会话同设备订单空历史最多复用1小时；换账号/外部订单变化后新建会话，不能继承旧证据。店铺状态、费用和ETA仍现场采集；尚无可用于跳过详情的商家缓存。详情与Checkout相差超过5分钟拒绝拼接。

商品优先识别价格上方同列标题，非Combo优先，Customisable为兜底；此启发式不保证无规格。只处理明确Required/Select 1单选，不勾可选项。已有可结算购物车优先读取。跨页商品按完整行合并，重名歧义/价格变化/不完整仍留partial，不凭空补齐。

金额为BRL整数分。单一服务费两列相同；明确Free为0。单一配送费在完整记录中还需总优惠与商品优惠/总额核算一致。ETA按同页采集时刻向上取整分钟，疑似过期/跨日歧义留空。未核实的ID、坐标、距离、会员字段留空。

## 异常页面与预算

正常页：主页、商家、详情、商品、Checkout、选地址、账号、订单历史。Checkout有Place order和Payment method是正常的，采集不按订单按钮。

优惠券、独立支付方式、支付/订单确认、明确广告、未知页：有界Back或明确广告Close/Dismiss/Skip ad返回。恢复后旧坐标和旧动作全部作废，重新定位；当前店已有信息保留partial与原因。

- 单次恢复最多3步，同页连续返回无变化即停止；每进程最多6次恢复，进店连续偏离最多额外重新定位2次。
- 页面稳定等待最多10秒；常见页连续两次文本稳定后继续。本地UI读取不等于后端请求数。
- 单轮列表最多4次滚动/6张候选卡；普通连续三店失败停止。预算耗尽不会无限刷新或重新进店。
- Access error、验证码/安全验证、空树/锁屏、外部App/支付、订单已提交页、地址无法确认、购物车冲突暂停，不自动跳过。
- 恢复日志仅记类别/动作/时间。未出现过的弹窗分类仍可能暂停；没有防封或持续吞吐量保证，VPN出口未核实。

## 证据、补解析与磁盘

内部会话保留SQLite、attempt元数据、字段来源、原始时间及错误。PNG只留最近10次，较早XML gzip压缩；JSON和账本保留。不删已写结果。

启动优先离线解析未提交且XML完整的尝试，不重新访问App；当前补解析只处理未压缩XML。每个新尝试保存所用账号上下文，旧证据无对应上下文则不补账号字段。完整金额校验后升级同一次尝试。

CSV/XLSX是唯一用户结果；导出器的JSON/XLSX临时文件在临时目录，用后释放。单条诊断工具仍可能写内部draft，由连续流程完成后清理。历史证据与废弃探针的归档位置见 [清理记录](cleanup-notes.md)。

## 单条离线诊断

```bash
python3 scripts/keeta_scripe-v4.py --parse-dir outputs/internal/streams/会话/attempt_某次
python3 scripts/keeta_scripe-v4.py --inspect-context-dir outputs/internal/streams/会话/attempt_某次
```

仅解析本地XML并写内部来源/草稿，不访问手机。为保留原始摘要，诊断历史证据前先复制到新内部目录。单条导出辅助命令 `--export-run` 使用 `export_keeta.mjs`，只对地址和金额校验通过的单条报价成对发布 `latest_时间戳.csv/xlsx`，不会覆盖已有同名结果；连续运行不使用此路径。

离线验证：`python3 -m unittest discover -s tests -v`。当前35项通过；实机长期成功率和规模尚未验收。

截止运行：基于SIGALRM可中断等待和采集；截止后禁用闹钟、停止唤醒线程、记录实际采集结束，再保存当前尝试及快照。导出完成时间另记export_finished_at。运行摘要保存在internal会话executions与run-status.json，Excel成功率页显示带UTC偏移的起止/截止时间。已过时的当天截止输入拒绝启动。离线测试包含真实短时闹钟中断测试。

## 持续模式

`--continuous`持续追加直到手动停止、可选截止或安全停止，忽略max-attempts上限。单窗口最多4次滚动/6张卡片后保存游标、等待至少180秒再推进；连续三个窗口无新店或12页深度预算耗尽则停止。游标只是当前首页顺序的近似位置，动态排序可能改变，店名去重仍执行，不保证全量覆盖。后台运行不代表会绕过安全停止。35项离线测试通过。
